# Магазин бытовой техники

Курсовой проект по разработке мобильного приложения корпоративной информационной системы. Android-приложение позволяет выбрать бытовую технику, оформить заказ с самовывозом в Казани и открыть электронный чек.

**10 категорий · 50 товаров · Android 10+**

## Возможности

- Вход и регистрация по российскому номеру телефона. Повторный вход открывает существующую учётную запись.
- Каталог с поиском по названию внутри категории и отображением цены и остатка.
- Корзина с подсчётом суммы. При добавлении того же товара увеличивается количество.
- Оформление заказа с самовывозом в пункте «Магазин бытовой техники, г. Казань».
- Демонстрационная онлайн-оплата без списания денег и электронный чек с датой, составом и суммой.
- Поиск своего заказа по номеру и повторное открытие чека.

Данные хранятся на устройстве. Для работы приложения после установки интернет не требуется.

## Запуск

1. Открой корень репозитория в Android Studio и дождись синхронизации Gradle.
2. Установи **Android SDK 37** через SDK Manager. Для Gradle используй встроенный JDK Android Studio.
3. Выбери эмулятор или устройство с **Android 10 (API 29)** или новее.
4. Запусти конфигурацию **app**. При первом открытии базы приложение добавит начальные данные.

Сборка и модульные тесты из корня проекта в Windows:

~~~powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest
~~~

APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

## Как проверить приложение

**Новый заказ.** Войди с новым номером, например `+7 999 000-00-50`, и открой **Каталог → Блендеры**. Добавь один товар дважды, перейди в **Корзину** и проверь количество. Оформи заказ, запомни его номер и нажми **Оплатить онлайн**. После оплаты откроется чек. Затем найди этот заказ по номеру во вкладке **Заказы**.

**Готовый чек.** Войди с демонстрационным номером `+7 000 000-00-01`. Во вкладке **Заказы** найди заказ `1` и нажми **Открыть чек**.

## Стек и структура

| Назначение | Технологии |
| --- | --- |
| Интерфейс | Kotlin, Jetpack Compose, Material 3 |
| Состояние экранов | MVI, ViewModel, StateFlow, Kotlin Coroutines |
| Навигация | Navigation Compose |
| Локальное хранилище | Room 2.6.1, SQLite, KSP |

~~~text
app/src/main/java/com/example/yamakoz/
├── MainActivity.kt       # Точка входа приложения
├── data/
│   ├── local/           # Room, сущности, DAO, триггеры и начальные данные
│   └── repository/      # Оформление, оплата и другие операции с данными
└── ui/
    ├── auth/            # Вход и регистрация
    ├── catalog/         # Категории, товары и поиск
    ├── cart/            # Корзина
    ├── order/           # Поиск, детали и оплата заказа
    ├── cheque/          # Электронный чек
    ├── navigation/      # NavHost и нижняя панель
    └── theme/           # Светлая и тёмная пастельные палитры
~~~

Отдельные файлы `*Route.kt` связывают Compose-экраны с их ViewModel и передают события навигации. Запросы к SQLite собраны в DAO, а многошаговые операции выполняет репозиторий.

## База данных

| Таблица | Что хранит | Записей при первом заполнении |
| --- | --- | ---: |
| `categories` | Категории с уникальными названиями | 10 |
| `products` | Товары, цены в копейках и остатки | 50 |
| `catalog` | Связи товаров с категориями | 50 |
| `customers` | Клиенты с уникальными номерами телефонов | 10 |
| `cart` | Количество каждого товара в корзине клиента | 10 |
| `orders` | Заказы с владельцем, составом, суммой и статусом | 10 |
| `cheques` | Электронные чеки, по одному на оплаченный заказ | 10 |

**Оформление.** В одной транзакции приложение проверяет, что корзина заполнена и товаров достаточно, создаёт заказ, списывает остатки и очищает корзину. При ошибке изменения откатываются.

**Оплата.** В отдельной транзакции заказ переходит из `awaiting_payment` в `paid` и получает чек. Попытка оплатить заказ повторно отклоняется.

**Целостность.** Внешние ключи связывают записи. Триггеры SQLite проверяют остатки, количество в корзине, допустимые статусы и соответствие чека оплаченному заказу. SQLite не поддерживает хранимые процедуры. Многошаговые операции реализованы транзакционными методами Room.

При обновлении базы с версии 1 до версии 2 миграция расширяет каталог до пяти товаров в каждой категории и сохраняет существующие записи.
